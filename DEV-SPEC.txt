SECTION 6: SLUG & ID RULES
================================================================

CITY SLUG (collision handling)
------------------------------
function generateCitySlug(cityName, stateName):
  base = slugify(cityName)
  if (no existing city with slug === base):
      return base
  else:
      return base + '-' + slugify(stateName)

  // Aurangabad Maharashtra -> 'aurangabad'  (first one wins)
  // Aurangabad Bihar       -> 'aurangabad-bihar'

RULE: Seeding ke waqt tier-1 city ko priority do,
      wo plain slug lega.
RULE: Ek baar assign hone ke baad slug NEVER change.
      Change karna pada to 301 redirect table maintain karo.


LOCALITY SLUG
-------------
  slugify(localityName)
  Unique WITHIN city only (compound index)
  "kanke-road" Ranchi aur Patna dono me ho sakta hai


LISTING SLUG
------------
  {bhk}-{propertyType}-{locality}-{city}-{price}-{nanoid6}

  Example:
  3-bhk-flat-kanke-road-ranchi-52-lakh-a7x9k2

  Rules:
  - Price humanize karo: 5200000 -> "52-lakh"
                         12500000 -> "1-25-crore"
  - Rent: 25000 -> "25k-rent"
  - nanoid(6) lowercase alphanumeric
  - Slug NEVER regenerate on edit (price change pe bhi nahi)
  - Reason: URL stable rehna chahiye SEO ke liye


DEALER SLUG
-----------
  slugify(businessName) + '-' + city.slug
  collision -> append nanoid(4)

SECTION 8: AUTH & AUTHORIZATION

DEALER OTP FLOW
---------------
1. POST send-otp
   - generate 6-digit OTP
   - store in Redis/Mongo with 10 min TTL
   - send via WhatsApp template 'login_otp'
   - rate limit 3/10min per phone

2. POST verify-otp
   - match OTP
   - if dealer doesn't exist -> create with status 'active',
     verificationTier 0
   - sign JWT { dealerId, role: 'dealer' }
   - httpOnly, secure, sameSite lax, 30 days

MIDDLEWARE RULES
----------------
/dealer/*  -> requires role 'dealer'
/admin/*   -> requires role 'admin'
/api/*     -> per-route check

OWNERSHIP CHECK
---------------
Listing edit/delete: listing.dealerId === session.dealerId
Lead read/update:    lead.assignedDealerId === session.dealerId

NEVER trust client-sent dealerId. Always session se lo.

FILTER SEGMENT PARSING
----------------------
Third segment ko parse karna hai. Supported patterns:

  flats                        -> propertyType
  plots                        -> propertyType
  3-bhk-flats                  -> bhk + propertyType
  flats-for-rent               -> propertyType + purpose
  3-bhk-flats-for-rent         -> bhk + propertyType + purpose
  flats-under-50-lakh          -> propertyType + maxPrice
  furnished-flats-for-rent     -> furnishing + type + purpose

Implementation:
  - Ek FILTER_PATTERNS registry banao (regex array)
  - Match na ho -> notFound()
  - IMPORTANT: unmatched pattern pe 404 do, warna
    infinite junk URLs index ho jayenge


404 / EMPTY STATE RULES
-----------------------
- City isActive false           -> 404
- Locality isActive false       -> 404
- Locality me 0 approved listing -> 404 (page render mat karo)
- Listing expired                -> 301 to locality page
- Listing deleted                -> 410 Gone

WEBHOOK FLOW
------------
POST /api/whatsapp/webhook

1. Verify X-Hub-Signature-256 (HMAC SHA256 with APP_SECRET)
   -> fail = 403
2. Return 200 IMMEDIATELY (Meta 20s me timeout karta hai)
3. Process async:

   a. Extract: from, messageId, text, profileName
   b. Upsert Conversation by phone
   c. Append message, set windowExpiresAt = now + 24h
   d. Parse "[Ref: xxx]" from message
      -> if found: listingId mil gaya
   e. Forward to n8n:

      POST {N8N_WEBHOOK_URL}
      {
        phone, profileName, message, messageId,
        listingId,              // null if generic
        listingContext: {       // if listingId present
          title, price, bhk, propertyType,
          locality, city, area, furnishing,
          possessionStatus, amenities
        },

        Kabhi reassign nahi (admin override chhod ke).


function routeLead(lead):

  // CASE A: listing-based lead
  if (lead.listingId) {
      listing = getListing(lead.listingId)
      dealer  = getDealer(listing.dealerId)

      if (dealer.status !== 'active')
          -> unmatched queue
      if (dealer.leadsUsedThisMonth >= dealer.maxLeadsPerMonth)
          -> mark lead 'quota-exceeded', admin queue,
             notify dealer to upgrade
      else
          -> assign(lead, dealer)
      return
  }

  // CASE B: generic lead
  candidates = Dealer.find({
      status: 'active',
      coverageCities: lead.cityId,
      $expr: { $lt: ['$leadsUsedThisMonth',
                     '$maxLeadsPerMonth'] }
  })

  // narrow by locality if known
  if (lead.localityId) {
      localityMatch = candidates.filter(d =>
          d.coverageLocalities.includes(lead.localityId))
      if (localityMatch.length > 0)
          candidates = localityMatch
  }

  if (candidates.length === 0)
      -> lead.status = 'unmatched'
      -> admin queue
      -> THIS IS A SALES SIGNAL: us city me dealer chahiye
      return

  // ranking
  sort candidates by:
      1. verificationTier   DESC
      2. rating             DESC
      3. lastAssignedAt     ASC     // round robin fairness

  assign(lead, candidates[0])


function assign(lead, dealer):
  lead.assignedDealerId = dealer._id
  lead.assignedAt       = now
  lead.isLocked         = true
  lead.status           = 'assigned'
  save

  dealer.leadsUsedThisMonth += 1
  dealer.totalLeadsReceived += 1
  dealer.lastAssignedAt      = now
  save

  if (lead.listingId)
      listing.leadCount += 1

  sendWhatsAppTemplate(dealer.phone, 'lead_assigned', {
      name, phone, budget, locality, timeline
  })


QUOTA RESET (cron, daily 00:05 IST)
-----------------------------------
  Dealers where quotaResetAt <= now:
      leadsUsedThisMonth = 0
      quotaResetAt = now + 30 days

SECTION 13: BUSINESS RULES (AUTHORITATIVE)
================================================================

LISTING LIFECYCLE
-----------------
  draft  -> dealer form incomplete
  pending -> submitted, admin review pending
  pending-location -> locality approval pending
  approved -> live on public site
  rejected -> admin rejected, reason stored
  expired  -> 30 days without refresh
  deleted  -> soft deleted

Transitions:
  draft -> pending           dealer submit
  pending -> approved        admin approve
  pending -> rejected        admin reject
  pending-location -> pending   admin approves locality
  approved -> expired        cron, expiresAt < now
  expired -> approved        dealer refresh
  any -> deleted             dealer/admin delete


EXPIRY CRON (daily 02:00 IST)
-----------------------------
  1. status='approved' AND expiresAt < now
     -> status = 'expired'
     -> recalculate locality.listingCount
     -> recalculate city.listingCount
     -> if locality.listingCount < 3 -> locality.isActive = false
     -> if city.listingCount < 25 -> DO NOT auto-deactivate
        city (manual decision), but alert admin

  2. expiresAt within 5 days AND status='approved'
     -> send 'listing_expiry_warning' template


CITY ACTIVATION (admin manual, with guard)
------------------------------------------
  Admin can set isActive = true ONLY IF:
      approvedListingCount >= 25
      verifiedDealerCount  >= 5   (tier >= 1)
      activeLocalityCount  >= 3

  API me ye check enforce karo, UI pe bharosa mat karo.


LOCALITY ACTIVATION (automatic)
-------------------------------
  isActive = true when:
      status === 'approved'
      AND introText.length >= 500 chars
      AND approvedListingCount >= 3

  Recalculate on every listing approve/expire.


VERIFICATION TIER RULES
-----------------------
  Tier 0: default
  Tier 1: pan.verified AND aadhaar.verified
  Tier 2: Tier 1 AND (gst.verified OR udyam.verified)
  Tier 3: Tier 2 AND rera.verified
  Tier 4: Tier 3 AND officePhoto.verified
          AND totalSiteVisits >= 5
          AND rating >= 4.0

  Tier compute automatic ho, par admin manually
  downgrade kar sake.

  Tier 0 dealer ki listing NEVER goes live.


RATING RULES
------------
  - Review only from Lead where status === 'site-visit-done'
  - One review per lead
  - dealer.rating = average of all reviewComment ratings
  - If rating < 3.0 AND ratingCount >= 5
    -> dealer.status = 'paused', no new leads
    -> admin alert

VALIDATION RULES
